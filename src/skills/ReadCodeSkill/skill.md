# ReadCodeSkill - 智能按行读取代码技能

## 技能描述

一个智能代码读取技能，专注于**按需读取代码片段**。与传统全量读取不同，本技能支持通过行号范围精确提取文件的特定代码行，从而大幅减少大语言模型的上下文空间占用，提高推理效率。

## 核心痛点解决

传统文件读取（如 `fs.readFileSync`）会将整个文件内容加载到上下文中，导致：
- 大文件消耗大量 Token，浪费资源
- 无关代码干扰 AI 对关键逻辑的判断
- 上下文窗口被快速填满，影响推理质量

**本技能通过分段读取机制，让 AI 只读取真正需要的代码行。**

## 可用工具

本技能可使用以下工具来辅助完成代码读取任务：

1. **ReadCodeLinesTool** - 按行号范围读取文件的指定代码行（核心工具）

## 使用流程

当用户需要查看代码时，遵循以下策略：

### 策略1：先浏览结构，再精确读取

&&&
步骤1: 如果用户没有指定具体行号，先用 FsTool 或 RunCommand 查看文件总行数/结构
步骤2: 使用 ReadCodeLinesTool 按行号范围读取关键代码段
&&&

### 策略2：直接按需读取

如果用户明确知道要读取的行号范围，直接调用 ReadCodeLinesTool。

## 典型场景

### 场景1：只读取函数定义

&&&
用户：帮我看看 src/core/BaseAgent.ts 中 run 方法的实现

我会先估算文件大小，然后调用 ReadCodeLinesTool 只读取包含 run 方法的部分
&&&

### 场景2：分段读取大文件

&&&
用户：读取 src/main.ts 的前50行看看

调用 ReadCodeLinesTool 读取第1-50行
&&&

### 场景3：对比两段代码

&&&
用户：帮我看看第100行到第150行和第200行到第250行的区别

分两次调用 ReadCodeLinesTool：
1. 读取第100-150行
2. 读取第200-250行
&&&

## 最佳实践

1. **先小后大**：不确定行号时，先读少量行（如头20行），再根据内容决定后续范围
2. **精确指定**：尽量精确指定行号范围，通常 30-50 行足够理解一个函数
3. **善用偏移**：看完一段后，如需看后续代码，基于上次的结束行号继续读取
